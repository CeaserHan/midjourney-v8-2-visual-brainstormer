# R4 关键帧

给视频模型（Seedance、可灵、Runway 等）做参考图。好看的单张图不等于好用的关键帧。两轮选择照常进行；R4 只改变交付结构和构图规则。

## 目录

1. 连续性卡
2. 构图规则
3. 首尾帧配对
4. 视频模型风险
5. 一致性手段
6. 自检

## 1. 连续性卡

交付开头输出连续性卡（格式见 [output-contract.md](output-contract.md) 第 8A 节）：角色、空间锚点、光、已选美术字段和画幅。卡里只写用户选择、连续性必需事实或公开的 X 决定；开放字段仍然开放。

每帧提示词都从连续性卡**重新写出**角色外形、空间锚点和主光，使用同一套英文措辞，不写 `same as previous`，不每帧换同义词。

## 2. 构图规则

- 画面停在动作开始前或进行中，不停在动作顶点。
- 运动方向前方留出空间。
- 主体轮廓与背景分得开，避免大面积遮挡主体。
- 画幅整组统一，写在代码块外；R4 的第二轮必须出现 F 画幅字段，用户选 F0 时在交付前补问一次，因为视频模型要求整组同一比例。

## 3. 首尾帧配对

- 两帧之间的变化要让视频模型补得出来：同一空间、同一光、同一风格。
- 一次只改变一个主要维度：主体位置或姿态变化；或机位推近；不同时换景别、换机位和换光。
- 用户要求转场或光线变化时，在中文里说明这一帧的变化是有意的。

## 4. 视频模型风险

剧情不需要时避开：手部特写、画面文字和招牌、复杂反射与镜面、细密重复图案、大量群众正脸。剧情必须有时，在代码块外提醒风险，不删用户要求的内容。

## 5. 一致性手段

- 用户有角色或场景参考图：Midjourney 用角色参考或图片参考，GPT Image 用图片输入并按 `Image 1` 写清用途（见各适配文件）。
- 没有参考图：建议先出一张角色定妆图，用它做后续帧的参考。
- 不编造参考图编号、链接或代码。

## 6. 自检

- 连续性卡是否在开头，且只含锁定内容？
- 每帧是否完整重写了角色、空间锚点和主光？
- 首尾帧之间是否只有一个主要变化？
- 是否停在动作进行中，并给运动留了空间？
- 风险元素是否已避开或已提醒？
