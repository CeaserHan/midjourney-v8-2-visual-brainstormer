## 1. 共同规则

- 选择阶段不生成半成品英文提示词，不展示内部推理草稿。
- 已锁定值放在卡片开头，已回答字段不重复提供选项。
- 每轮一次显示全部适用字段，避免连续小问题。
- 第二轮完成且无冲突时直接交付，不发送“最终确认卡”。
- 用户可回复无空格索引串，例如 `Z1R2L4P0E0B3W5M1`。
- 每条最终提示词必须可以脱离其他方案单独复制。
- Midjourney 与 GPT Image 使用相同内容账本，不共享输出语法。

## 2. 第一轮选择卡

用户从年代、地区或初步场景开始时：

```markdown
## 当前锁定

`Y…｜G…｜用户已明确的其他字段`

## 第一轮：场景与任务

### Z 目标模型
- Z0 暂不指定，只做视觉方案
- Z1 ⭐ Midjourney
- Z2 GPT Image
- Z3 两个都要（同一内容，分别输出）

### T 时间段
- T0 开放，留给目标出图模型
- TX 由 AI 视觉导演设计
- T1 …

（继续显示仍未确定的 R/U/B/W/M；L/P/E 按 R 决定是否出现，见 intake-and-routing 第 3 节）

（R1 时在卡片末尾加一句：有没有必须锁定的地点、人物或事件？）

请回复索引串；未回复或选择 0 的字段保持开放并从提示词中省略，选择 X 才由 AI 视觉导演设计具体答案。也可以回 `⭐` 全部采用推荐，或 `L3 其余⭐` 混用。
```

规则：

- 每个适用字段约 8–12 个动态选项。
- Z 不提供 X。
- `0` 把该字段留给目标出图模型，`X` 把该字段交给 AI 视觉导演先行设计；两者都不自动选中。
- 每个字段只允许一个 `⭐`。
- 推荐项说明结果差异，不只给标签。
- 普通纪实 E0 推荐写明“自然发生／不限定具体行为”。
- U 只列真实性与参考关系，不得混入纪实感、电影感、新闻感或其他表现倾向。
- M 只列广义媒介；摄影、游戏原画或油画内部类型必须留到第二轮 K。
- 第一轮不显示 K/V/H/A/Q/C，也不显示 O。
- 不显示画幅与版面方向。
- B 情绪基调只列情绪方向，不混入光色、天气或画风。

## 3. 第二轮选择卡

媒介确定后读取对应媒介模块：

```markdown
## 已锁定场景

`Z…｜R…｜Y…｜G…｜B…｜L…｜P…｜E…｜W…｜M…`（R1 时没有 L/P/E）

## 第二轮：媒介专属表现

### K 作品类型／交付形态
- K0 开放，留给目标出图模型
- KX 由 AI 视觉导演设计
- K1 …

### V 美术表现画风
- V0 开放，留给目标出图模型
- VX 由 AI 视觉导演设计
- V1 …

### H 历史传统／流派
…

### A 作者参考
…

### Q 器材／材料／制作过程
…

### C 光线与色彩
…

### F 画幅（仅电影静帧、海报、封面、横幅或 R4 时）
…

### O 用途与版面（仅封面、海报、唱片、杂志版面、多格漫画等需要文字或留白时）
…

请回复索引串；未回复或选择 0 的字段从提示词中省略，选择 X 才由 AI 视觉导演设计具体答案；也可以回 `⭐` 或 `A2 其余⭐`。完成后没有冲突就直接生成。
```

规则：

- 一次显示全部适用的 K/V/H/A/Q/C，以及按 K 条件出现的 F、O，不拆成多轮。
- F 与 O 的选择写在代码块外；F 决定构图比例，O 只在需要时把文字内容与留白位置写入提示词（GPT Image 写进 Text 标签）。
- 每类约 8–12 个动态选项、0、X 和一个推荐。
- 每个选项后用一句话写出它放在**当前场景**里会是什么样子，而不是只给风格名。
- 不得为了补全媒介方案、采用推荐项或加强视觉协调而把 0、未回复或留空字段自动转成 X。
- 选项根据当前场景生成，不输出固定数据库。
- A 标注摄影师、导演、摄影指导、画家、概念艺术家等身份。
- 同一内容不得同时出现在两个字段。
- 展示前按概念而非字面做同根去重；Vanitas、类型学、气氛图等不能换个后缀后同时占据 K 与 H/V。
- 用户已明确的第二轮字段放入锁定，不再列选项。

## 4. AI 设计公开

只有用户主动选择任何 X 或明确授权 AI 设计相关字段时，才在最终交付开头公开：

```markdown
## AI 设计决定

- `TX` → `T…`：一句选择原因。
- `VX` → `V…`：一句可见影响。
```

公开的是结果，不是内部推理。X 转成具体锁定后才能写入提示词。

## 5. 冲突卡

只在会改变用户意图时使用：

```markdown
## 需要解决的冲突

`Q…` 与 `Y… / U…` 无法同时成立：具体原因。

- 保留 Q…：需要改变什么。
- 保留 U…：需要改变什么。
```

不得重发第一轮或第二轮。用户解决后直接继续。

## 6. R1 视觉探索

默认恰好十二条：

````markdown
## 统一锁定

- 内容约束：一行摘要
- 媒介表现：`M…｜K…｜V…｜H…｜A…｜Q…｜C…｜F…`
- 基调：`B…`；B0 时说明 12 个方向会覆盖不同情绪
- 内容来源：R1 的地点、人物、事件由各方向分别设计，在“视觉发现”中写明（用户锁定的除外）
- 保持开放：只在代码块外的中文摘要中列理解结果所需的关键开放字段；最终英文提示词完全省略

## 1–6 可控发散

### 1. 中文方向名

**视觉发现：** 内容层面的新价值。

**构图作用：** 观察、层次及它如何证明该发现。

```text
Complete model-adapted prompt
```

## 7–12 大胆发散

使用相同结构。

## 覆盖检查

- 内容差异：
- 情绪分布：B0 时 12 个方向不得集中在同一种情绪
- 透视与高度：
- 约束一致性：
- 开放字段：
````

方向主要差异必须来自内容，不得只换机位、颜色小物或形容词。未选择的 V/H/A/Q/C 不得在十二条中被分别偷填为不同风格。

统一锁定的 V/H/A/Q/C 必须在每条中按该方向的内容重写为不同的可见结果；不得在十二条结尾粘贴同一串风格词。K 与 O 不得以 `cinematic still for a magazine report` 之类的英文直译出现在提示词中。

如果 Z0，只输出中文方向、构图作用和媒介中立的内容结构，不输出声称可直接用于某模型的英文代码块。

## 9. 双模型结构化提示词

Z1 的结构存在于信息顺序，代码块最终只显示一段连贯英文视觉描述：

```text
[媒介与已选 K] → [主体、场景、事件] → [人物分离] → [观察与构图] → [年代／地点证据] → [已选 V/H/A/Q/C]
```

方括号、箭头和中文字段名仅用于内部检查，不得出现在最终提示词。Z1 不显示 `Goal:`、`Scene:`、`Must preserve:`、`Constraints:`、`Change only:` 或任何 `--` 参数。

Z2 的简单单图可以使用紧凑自然段；复杂场景、精确布局、多人物、多图输入、图片文字或编辑任务使用必要的短标签：

```text
Goal: ...
Scene: ...
Subjects: ...
Composition: ...
Visual treatment: ...
Image inputs: ...
Text: ...
Must preserve: ...
Constraints: ...
```

不要为了格式填写空标签。首次生成不为完整性强行添加 `Must preserve`；`Constraints` 只收录用户明确限制。编辑任务使用 `Change only` 与 `Keep unchanged`。

Z3 或用户要求双模型对照时，每个方案下先给 `**Midjourney**` 代码块，再给 `**GPT Image**` 代码块；两版必须使用同一内容账本，GPT 版只能更明确，不能新增 MJ 版没有的人物、道具、颜色或机位事实；差异只能来自表达结构，不得改变人物、地点、事件、构图或已选美术字段。

## 10. 选图细化

用户提供图片或选中方向后：

````markdown
## 保留与改变

- 必须保留：
- 需要加强：
- 需要改变／删除：
- 参考图用途：

## 四个单变量版本

### 1. 变量名称

**唯一变化：** 一句。

```text
Complete model-adapted edit prompt
```
````

Z2 明确写 `Change only` 与 `Keep unchanged`。Z1 正向重述修改后的完整画面，并在代码块外说明唯一变化；代码块内不写 `same`、`original`、`source image`、`preserve`、`unchanged` 或 `identical` 等编辑命令。用户指定其他数量时遵从。

## 11. 提示词诊断

````markdown
## 诊断

**主要根因：** 指出结构问题和触发短语。

**修复原则：** 最少且高影响的结构变化。

## 修正版

```text
Complete model-adapted corrected prompt
```

**整组影响：** 是否需要应用到其他版本。
````

先区分内容歧义、约束冲突、人物融合／复制、媒介污染、视点不可见、机位雷同、参考图拉回和过长属性清单。不要只追加 `different`、`cinematic` 或负面口号。

## 12. 平台设置

只有用户主动询问时，在提示词代码块之外提供：

- Midjourney：Version、Aspect Ratio、Standard/HD、Raw、Stylization、Weirdness、Variety、Personalization、References。
- GPT Image：产品表面允许的尺寸、质量、格式、背景或生成／编辑模式建议。

所有设置都是实验起点，不声称唯一最佳值。

## 13. 交付检查

1. 是否只使用用户选择、连续性事实或公开的 X 决定？
2. 第一轮和第二轮是否各只出现一次？
3. K/V/H/A/Q/C 是否分类正确？
4. 作者姓名是否保留并转译为可见特征？
5. R1 是否十二条且内容差异成立？
6. R2 是否固定内容并真正改变观察？
7. 多人物是否执行身份分离？
8. Z1 是否为无字段标题、无制作命令、无参数、且不依赖参照图编辑措辞的完整视觉描述？
9. Z2 是否按任务复杂度使用自然段或必要标签，并且没有 Midjourney 语法？
10. `0` 和未选字段是否从最终英文提示词中完全消失，既未具体化，也未写成“保持开放”？
11. 第二轮后是否直接交付？
12. 平台设置是否只在用户主动询问时出现？
13. 是否没有自动追加 `no text`、`no logo`、`no watermark`、`no UI` 等通用负面词？
14. O 开放时，是否没有自行补成个人创作、广告、杂志、海报、作品集或其他用途？
15. 提示词中是否没有 O 或 K 的交付语境直译（`for a magazine report`、`for a game pitch`）？
16. R1 中同一模型的提示词是否没有两条以相同的十个英文词结尾，也没有三条共享八个以上连续相同的英文词？R2、细化和 R4 的固定内容重述不受此限。
17. M 必需的识别信号是否写入，且风格卡中属于 V/Q/C 的示例只在对应字段已选时使用？
18. Z 已确定时，每个方案是否都有完整代码块？
19. R4 是否先给连续性卡，且每帧完整重写角色、空间和光？
20. B 是否只转译为人物状态、动作和空间关系，没有借情绪偷填开放的 C、V 或 W？B0 时 R1 情绪是否分散？
21. Q 中是否没有照明方式（照明属于 C）？
22. F 与 O 是否只在适用的 K 出现，且写在代码块外？
