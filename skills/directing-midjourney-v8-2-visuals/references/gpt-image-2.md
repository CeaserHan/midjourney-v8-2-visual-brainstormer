# GPT Image 2 提示规则

核验基准：2026-08-10。功能、模型可用性和接口设置可能更新；用户要求精确当前事实时核对 OpenAI 官方文档。

## 1. 提示结构

- 把提示词写成明确的制作指令，不写成 Midjourney 关键词串。
- 单一主体、单一场景、无精确布局、无图片文字、无多图输入且不是编辑任务时，使用紧凑自然段。
- 复杂场景、精确布局、多人物、多图输入、图片文字或编辑任务时，使用必要的短标签：

```text
Goal:
Scene:
Subjects:
Composition:
Visual treatment:
Image inputs:
Text:
Must preserve:
Constraints:
```

- `Goal` 只写生成／编辑动作及用户已选 M/K/O；用途开放时，不补成个人创作、广告、杂志、海报或作品集。
- `Scene` 只写地点、年代、时间、天气、环境和事件。
- `Subjects` 分别写每个主体的身份、外形、动作、方向、位置和互动。
- `Composition` 写景别、观察高度、视角、透视、框景、负空间及前中后景。
- `Visual treatment` 只写已选 V/H/A/Q/C 的可见结果。
- `Image inputs` 按 `Image 1`、`Image 2` 说明每张真实输入图提供主体、风格、布局或材料中的哪一项。
- `Text` 写用户要求出现在图片中的准确文字、位置、字体类别、大小、颜色和层级。
- `Must preserve` 只写编辑连续性或精确布局需要保持的不变量；首次生成不为完整性强行添加。
- `Constraints` 只写用户明确的排除、文字、数量或硬限制；不自动追加通用负面词。
- 没有已锁定内容或连续性事实的标签直接省略，不显示空标签。
- 具体说明材料、形状、纹理、媒介、构图、视点、人物动作和物体交互。
- 写实摄影需要时直接说明 photorealistic、real photograph 或相当的真实摄影意图。
- 详细相机参数可能被宽松理解；同时说明观察位置、主体距离和最终空间效果。

## 2. 构图与人物

- 明确景别、观察高度、方向、透视、主体位置、负空间和前中后景。
- 人物说明身体取景、尺度、视线、手部与物体互动。
- 多人物使用独立身份账本，不依赖单写 `different people`。
- 布局敏感时明确元素位置，但不承诺像素级精确放置。

## 3. 生成与编辑

第一次生成可以使用完整制作指令。编辑时使用：

```text
Change only: [one intended change]
Keep unchanged: [identity, geometry, layout, objects, lighting, color, or other invariants]
```

单次优先一个高影响变化。多轮编辑重复最关键的保留项，防止漂移。用户要求完全重做时不要错误保留旧构图。

编辑代码块不得退化为一条全新 Midjourney 式描述；明确区分本轮唯一变化与必须保持的身份、几何、布局、对象或光色。

## 4. 多图片输入

- 按 `Image 1: ...`、`Image 2: ...` 编号并描述用途。
- 明确哪张提供主体、哪张提供风格、哪张提供布局或材料。
- 说明元素如何组合，避免只写“参考这些图”。
- 不虚构不存在的图片编号、URL 或文件。

## 5. 图片文字

- 字面文字使用引号或全大写。
- 说明准确拼写、位置、字体类别、大小、颜色和层级。
- 难词可以逐字母拼写，但不承诺绝对准确。
- 用户未要求文字时，不讨论文字控制，也不自动追加 `no text`、`no logo`、`no watermark` 或 `no UI`。场景事实需要的年代标识和自然招牌按真实性选择处理。

## 6. 设置分离

尺寸、质量、格式、压缩、背景和生成／编辑动作属于产品或 API 设置。只有用户主动询问时，在提示词外单独建议。

## 7. 已知边界

- 跨多次生成的人物或品牌一致性仍可能漂移。
- 精确布局和文字位置仍可能出现偏差。
- 复杂提示可能需要通过小步迭代调试。
- 作者姓名的接受和表现受目标产品行为与政策约束；保留姓名不等于承诺精确复制。

通用负面词清单会把开放字段变成新约束。只有用户明确排除、用途硬性要求或编辑连续性需要时，才写对应的排除项或结构修复。
